# Connectors and manual end tiles

## Intent

Let the solver join names that share no letter by using a single decorative tile, and let the user add or remove a blank decorative tile at the end of any name. This is the layout half of Phase 3 in `../SPEC.md` §21.

## Background

The solver (PR #4, merged) only joins names through shared letters. Names with no shared letter currently get a message and no crossword, which blocks real orders. `../SPEC.md` §6.4 as amended under CHG-0003 defines the two allowed connector shapes (L-corner and T) and the rule of one tile between two names. The saved data model already has the fields a connector needs (`anchor`, `joinsNameId`), and the validator currently rejects every decorative tile as "not supported yet".

Phase 3 also lists artwork (built-in pictures and uploaded SVGs). That is proposed as its own following task, because uploaded SVG needs separate safety work and does not affect the layout.

Linear tickets: None.

**Status: Approved by the user on 2026-11-14**, with these decisions: artwork is a separate following task; no switch to turn automatic connectors off; one decorative tile per name end; a small heart as the placeholder marker (changed from an outline to a filled heart by the user on 2026-11-14); the security section as proposed; the search mode defaults to Balanced.

## Acceptance criteria

- AC1: The validator accepts a decorative tile only when it sits on the empty square just before the first or just after the last character of its anchor name, in line with that name.
- AC2: The validator accepts a connector only in the two shapes of `../SPEC.md` §6.4: L-corner (the joined name starts or ends on the square next to the tile, perpendicular to the anchor name) and T-shape (the joined name runs past the tile side-on, touching it with one square). The two names must be perpendicular.
- AC3: The validator reports, by name, each of these: a connector joining parallel names, two connectors between the same pair of names, a chain of two decorative tiles, a tile inside a name or on an occupied square, a tile touching a square of any name other than its anchor and its joined name, and a manual decoration touching anything except the end square of its anchor name.
- AC4: Connectivity is counted through shared-letter intersections and connectors only. A crossword joined only by contact is still reported as disconnected.
- AC5: When names cannot all be joined by shared letters, the solver returns complete layouts that use connectors. Every name is present and whole, and every returned layout passes the validator.
- AC6: The solver uses a connector only where a shared-letter placement is not available for that name at that step, and layouts with fewer connectors rank higher under the default weights. Names that can be fully joined by shared letters give the same results as before this change.
- AC7: After a connector joins a group, later names may again join by shared letters with any name already placed.
- AC8: If no valid layout exists even with connectors, the solver returns no layout and a clear message. It never returns a partial crossword as complete.
- AC9: The few-connectors score counts automatic connectors only. Manual decorations do not lower a layout's score.
- AC10: In the app, connector tiles are drawn as tiles with a marker that distinguishes them from letter tiles. Each candidate shows its connector count.
- AC11: In the app, the user can add a blank decorative tile at any eligible end of a name in the selected layout and remove any manual tile. Ineligible ends are not offered. Adding or removing a tile does not regenerate the crossword, and the change is saved with the project.
- AC12: Fit checking, the red out-of-area marking and the bounding-box centring include decorative tiles.
- AC13: Generating again replaces the layout, including manual tiles, as `../SPEC.md` §6.5 allows.
- AC14: Ten names with connectors needed stay inside the existing time limits: Quick 1 second, Balanced 3, Thorough 10. The same input and seed give the same result.
- AC15: Automated tests cover the remaining solver cases in `../SPEC.md` §20 (two names with no shared characters, valid single-tile connector, invalid two-tile chain, connector between parallel names, connector at an interior position, manual end tile), plus AC3–AC9 and AC14.

## Constraints / Architecture direction

- Perform implementation and validation in a dedicated task worktree. Preserve the user's original checkout and all existing local changes.
- The validator stays the single source of the rules. The search and the manual-tile editor both use it; the editor offers only positions the validator accepts.
- The solver stays in `src/core` with no React, DOM, Node, font or drawing dependencies, seeded randomness only, and counted search budgets.
- The adjacency rules of `../SPEC.md` §6.1 as amended apply unchanged: a tile may touch only its anchor name and, for a connector, its joined name.
- A tile's `artworkId` stays `null` (blank) in this task. The preview marker is a placeholder drawn by the app, not saved artwork.
- No new dependencies. Keep code comments brief.

## Security considerations

Proposed during drafting; to be confirmed by the user.

- No new API routes, no uploads and no new dependencies.
- Saved decorative tiles are untrusted data when a project is loaded: count-limited, coordinate-limited and checked by the validator before being drawn.
- Search budgets still bound the work, with connectors included.

## Out of scope

- Built-in artwork, uploaded SVG, and choosing a picture per tile (proposed next task).
- Engraving of artwork and crossword cut geometry (Phase 4).
- Dragging tiles or names, and adding tiles anywhere other than a name end.
- Keeping manual tiles when generating again.
