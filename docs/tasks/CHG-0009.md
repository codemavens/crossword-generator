# Workspace UI: step rail, always-visible preview and one control panel

## Intent

Replace the single long page of seven stacked panels with a three-part workspace, so the preview and the controls that change it are on screen together and the work reads as an ordered set of steps. Every control, message and behaviour the app has today stays; only where it sits and how it looks changes.

The approved mockup is the visual reference: https://claude.ai/artifact/RngzKWgLHiEagijXWaPVqZ

## Background

The user reviewed the app on 2026-11-14 and found the UI "extremely basic and cluttered". The facts behind that:

- The preview sits below about 20 form fields, so a change and its effect are never visible together, and the preview is capped at 560 px wide.
- Generate, the main action, is the last thing on the page, below Export.
- Seven panels share one visual weight, and status messages appear in seven different places.

A mockup was produced the same day and the user approved its direction ("that looks a lot better. Spec it out"). These decisions were confirmed by the user on 2026-11-14 and are written into this brief:

- Steps unlock in order; any earlier step can be reopened at any time.
- Arrangement is the second step, straight after Details, so the crossword layout is visible before the frame and other settings are adjusted.
- The step completion rules in AC7.
- The title stays "Sloth & Llama Name Art Designer".
- Below about 1000 px the three parts stack vertically.
- The change is delivered as one pull request.
- The five weight labels drop the word "weight", and the weights sit in a section that is closed by default.
- Delete project and Remove font use a styled confirmation dialog, not the browser's own.
- The security section as written.

**Status: Approved by the user on 2026-11-14.**

This work builds on CHG-0008, which was merged into `develop` in pull request #11. The branch `feature/workspace-ui` starts from that merge.

## Acceptance criteria

### Layout

- AC1: The page is a top bar above three parts: a step rail on the left, the preview in the centre, and one control panel on the right. At 1280 px wide and above, all three are visible without scrolling the page sideways, and the preview stays on screen while the control panel is used.
- AC2: The top bar shows the title "Sloth & Llama Name Art Designer", the current project's name (or "New project" for an unsaved one), the save status, and the Save button. The browser tab title is unchanged.
- AC3: Below about 1000 px wide the rail, preview and control panel stack vertically in that order. Nothing is cut off and the page does not scroll sideways.
- AC4: The preview is no longer capped at 560 px; it grows to fill the centre area while staying square and fully visible.

### Step rail

- AC5: The rail lists Projects, then six numbered steps in this order: Details, Arrangement, Fonts, Frame, Tiles, Export. The control panel shows only the selected entry's controls.
- AC6: Each step shows a one-line summary of its current state: the number of names; the chosen arrangement or "None chosen"; the chosen font names; the outer diameter; the tile size; "Ready" or "Not ready".
- AC7: A step is complete when:
  - Details: the project name is filled in, there is at least one name, and no name is invalid. The project does not have to be saved.
  - Arrangement: an arrangement is chosen and still matches the names.
  - Fonts: all three chosen fonts are loaded and available.
  - Frame: no frame field has an error and the frame builds. Frame warnings do not count; Export already blocks on them.
  - Tiles: tile size and letter size are valid.
- AC8: A step can be opened when every step before it is complete. A locked step is shown as locked, cannot be opened by mouse or keyboard, and says which earlier step needs attention. The current step and every earlier step can always be opened, in any order.
- AC8a: Generate needs a frame, and the frame needs the fonts to load. If the fonts could not be loaded while no arrangement is chosen, Fonts is unlocked so another font can be chosen, and the Arrangement panel says so beside Generate. If the frame fails to build for any other reason, the Arrangement panel shows the error message.
- AC9: Completion is worked out from the project as it is now, not remembered. Opening a saved, finished project unlocks all six steps. If a step being viewed becomes locked by a change elsewhere (for example a font removed from the library), the view stays where it is and the rail marks the step that needs attention.
- AC10: Projects is always available. Opening, creating, duplicating or importing a project shows that project at the Details step.
- AC11: Each step's panel ends with a "Next" button naming the following step. It is disabled while that step is locked. Export has no "Next".

### Control panel contents

- AC12: Projects holds New, the search box, Import project…, and the project list with Open, Duplicate and Delete on each project. The open project is highlighted.
- AC13: Details holds Project name, Customer name, Family name, Year, the Names list with Add name and Remove, and Export project (JSON). The Names heading shows the count out of 20.
- AC14: Fonts holds the three font selects, each with a sample in the chosen font, plus Add fonts… with its upload results, and Manage fonts.
- AC15: Frame holds the same ten controls as today, grouped as: Size (Outer diameter with its slider and Smallest that fits); Ring and clearance (Ring width, Gap between crossword and frame); Family name and year (Family name font size, Year font size, Name buffer, Name drop below line); Base (Bottom line height, Bottom corner radius); and the Outline slider, which now shows its value.
- AC16: Tiles holds Tile size with its slider and Largest that fits, Letter size with its slider, Show point values, and a second Edit end tiles button that does the same as the one above the preview.
- AC17: Arrangement holds Search mode, Seed, New seed and Generate at the top; the five weights and Reset to defaults in a collapsible "Scoring weights" section, closed by default; and the arrangement list. Inside that section the labels are Circular fit, Compactness, Visual balance, Natural intersections and Few connectors. Each arrangement shows its thumbnail, number, score, breakdown and statistics, and the chosen one is marked "Selected".
- AC18: Export holds a readiness card, the three Operation colours with Reset colours, the three downloads with their sizes, Download all three, and Download proof image (PNG). The readiness card says "Ready to export" when nothing blocks export; otherwise it lists every blocker exactly as today, and each blocker names the step that fixes it.
- AC19: Millimetre and percent units are shown inside the number fields, not in the labels. Each field keeps an accessible name that includes its unit.

### Preview area

- AC20: Above the preview: Edit end tiles, Centre, the position readout, and the six layer toggles (Frame, Backer, Cut lines, Score lines, Engraving, Crossword) as on/off chips. Each chip carries the colour of its layer in the preview. The toggles stay view-only and are not saved.
- AC21: The help line under the toolbar shows the same three texts as today for editing, moving and neither.
- AC22: While end tiles are being edited and a tile is selected, the tile editor opens as a panel over the corner of the preview, with the same contents as today: the picture choices, Upload SVG…, Remove tile, Close, and the uploaded pictures with Delete.
- AC23: Below the preview, a Size and fit bar shows Tile size, Frame diameter, Crossword size and the fit result. "Generate to see arrangements." and the names-changed warning appear in the preview area.
- AC24: Dragging the crossword, moving it with the arrow keys (Shift for 5 mm), and the live fit check while dragging all behave as today.

### Messages

- AC25: Every message, warning, error, empty state, busy label and confirmation the app shows today is still shown, with the same wording and under the same conditions.
- AC26: A message about one control appears next to that control. "Saved.", "Duplicated. You are now editing the copy." and "Imported as a new project." appear as the save status in the top bar. Errors from saving, loading or importing appear in one place directly under the top bar.
- AC26a: Delete project and Remove font ask for confirmation in a styled dialog in place of the browser's own. The dialog shows the same question, has Cancel and a clearly marked destructive button, starts with focus on Cancel, closes on Escape without acting, keeps keyboard focus inside while open, and returns focus to the button that opened it.
- AC27: The "Export anyway" confirmation appears in the Export panel above the downloads, under the same conditions and with the same reset rules as today.

### Behaviour, access and proof

- AC28: Saved projects, exported SVG files, the proof image and the project JSON are byte-for-byte what the same inputs produce before this change.
- AC29: Every control can be reached and used from the keyboard, focus is always visible, and pressing Enter in a Details field still saves. Toggle buttons report their pressed state, and status and error messages are still announced.
- AC30: Text and controls meet 4.5:1 contrast against their background. States shown by colour (selected, locked, warning, fits) are also shown by text or an icon.
- AC31: Existing tests pass. New automated tests cover the unlock rules in AC7–AC9 and the confirmation dialog's questions and decisions. The repository has no browser test tooling and this task adds none, so the layout and the dialog's focus behaviour are checked by hand in the running app.
- AC32: `README.md`, `docs/SPEC.md` and `docs/handover.md` describe the new layout wherever they describe the old one.

## Constraints / Architecture direction

- Perform implementation and validation in a dedicated task worktree. Preserve the user's original checkout and all existing local changes.
- UI only: changes stay inside `src/app` and `index.html`. No changes to `src/core`, `server`, the API, the project model or stored data.
- The selected step, the layer toggles and open or closed sections are view state. They are not saved with the project.
- The unlock rules read the validation and state the app already computes. They are not a second copy of the validation.
- Keep the stack as it is: React with plain CSS in `src/app/styles.css`. No UI component library, CSS framework or icon package. Icons are small inline SVGs.
- Fonts for the interface come from the system font stack; the app stays usable offline. Pacifico and Zilla Slab remain bundled for the design only.
- Colours and spacing are defined once as CSS variables and follow the mockup's light theme: a neutral grey background, white surfaces and one teal accent.
- Keep existing accessible names and labels where tests or screen readers rely on them, except where AC19 changes a label.
- One pull request into `develop`.

## Security considerations

- No new endpoints, permissions, external calls or stored data. The app stays a local tool with no accounts.
- No new network requests: the interface must not load fonts, scripts or styles from the internet.
- File inputs keep their existing limits and checks (project JSON 2 MB, fonts 10 MB, SVG conversion and the 20-picture cap). Moving them must not bypass or loosen any check.
- Project names, customer names, font names and file names continue to be rendered as text, never as HTML.
- Delete project and Remove font keep a confirmation step before the irreversible action. The styled dialog must not act on Enter by default or on a click outside it.

## Out of scope

- Any change to solver, geometry, export, validation rules or the server.
- New capabilities: zoom or pan, undo, autosave, an unsaved-changes indicator, dark mode, or drag-and-drop upload.
- Making the preview's cut and score lines follow the Operation colours; they stay red and blue.
- Dedicated phone or tablet layouts beyond the stacking in AC3.
- Reordering or rewording the fields themselves, beyond the grouping in AC15 and the unit change in AC19.
