# Crossword solver: natural-intersection layouts, scoring and fit

## Intent

Generate several valid crossword arrangements from the list of names, rank them with the configurable weights, and show the chosen one inside the real frame opening with a clear fit result. This is Phase 2 in `../SPEC.md` §21.

## Background

Phase 1 (PR #1), the spec amendments (PR #2) and the frame prototype (PR #3, shape approved by the user on 2026-11-13) are done. The frame geometry now provides the usable opening as polygon data, which the solver's circular-fit score and the fit test need. The app still shows only a hand-built sample crossword.

`../SPEC.md` §21 says connector logic must wait until natural intersections are reliable, so connectors are a separate, later task.

Linear tickets: None.

**Status: Approved by the user on 2026-11-13**, including the proposed limits (20 names, 30 characters), up to 8 candidates, the zero-weight ranking and the security section.

## Acceptance criteria

- AC1: Name text is normalised as `../SPEC.md` §5.3 (amended) and §7.2 step 1 describe: trimmed, NFC, uppercase, curly apostrophes matched as plain ones. Names shorter than two characters, with spaces, or with unsupported characters are rejected with a message.
- AC2: A solver module in `src/core` takes the names, solver settings (seed, search mode, weights), and the usable opening in tile units with the minimum gap. It returns a ranked list of distinct layouts, each with placements, bounds, intersection count, score breakdown, fit result, validation issues and seed.
- AC3: Every returned layout passes a validator that is separate from the search and enforces `../SPEC.md` §6.1 as amended: every name present exactly once, horizontal or vertical, perpendicular crossings on identical characters only, no side-by-side contact between different names, the squares before and after each name empty, one connected piece counted through intersections only.
- AC4: The same validator can be run on any layout (for example a saved one) and reports each structural error in `../SPEC.md` §19.1 that applies without connectors, by name.
- AC5: Two names with identical text are placed as two separate names.
- AC6: Matching apostrophes and matching hyphens can intersect. An apostrophe never intersects a hyphen or a letter, and É never intersects E.
- AC7: The same names, settings and seed always give the same ranked list. A different seed can give a different list.
- AC8: Returned layouts are distinct: none is a shifted, mirrored or rotated copy of another.
- AC9: Scoring follows `../SPEC.md` §8: five metrics each between 0 and 1, combined as a weighted average. A zero weight switches a preference off. With all weights zero, a documented fixed ranking is used.
- AC10: Circular fit and the fit test use the real usable opening from the frame geometry, shrunk by `crosswordClearanceMm`, with the crossword centred as `../SPEC.md` §9 (amended) describes. A layout that does not fit is still returned, marked as not fitting.
- AC11: When the names cannot all be joined by natural intersections, the solver returns no layout and a message naming the groups that could not be joined. It does not fail silently or return a partial crossword as if it were complete.
- AC12: Quick, Balanced and Thorough modes change only the search effort, never the rules. For ten names on this machine: Quick finishes within 1 second, Balanced within 3, Thorough within 10.
- AC13: In the app, a Generate button runs the solver without freezing the page, lists the candidates with their score breakdown, and lets the user pick one. The picked layout is saved with the project and shown again after reopening.
- AC14: The app has a control for each of the five weights with its current value, a Reset to Defaults button, a search-mode choice and a seed field. Changing a weight does not change the layout already shown; it takes effect on the next Generate.
- AC15: The picked layout is drawn inside the frame preview at true scale. Tiles outside the allowed area are visibly marked and a warning says the crossword does not fit.
- AC16: The saved layout uses the data model from `../SPEC.md` §15 as amended (`decorativeTiles` instead of `connectors`, with `anchor` and `joinsNameId`). A project saved before this change still opens.
- AC17: Automated tests cover the solver cases in `../SPEC.md` §20 that do not need connectors, AC5–AC11, and one ten-name run per search mode.

## Constraints / Architecture direction

- Perform implementation and validation in a dedicated task worktree. Preserve the user's original checkout and all existing local changes.
- The solver and validator live in `src/core` with no React, DOM, Node, font or drawing dependencies. The opening reaches the solver as plain polygon data.
- A custom search written in TypeScript, as `../SPEC.md` §7.1 requires: multi-start, bounded beam search or similar. No crossword-generation library and no new dependencies.
- Randomness comes only from a seeded generator owned by the solver. No `Math.random` and no clock in the search.
- Validation is separate from candidate generation and is the single source of the rules, so the connector task and manual editing reuse it.
- In the browser the solver runs off the main thread (a Web Worker), so a Thorough run cannot freeze the page.
- The fit test is geometry on the existing frame output; `clipper2-ts` stays behind the existing polygon module.
- The branch is stacked on `feature/frame-prototype` (PR #3) until that is merged.
- Keep code comments brief.

## Security considerations

Proposed during drafting; to be confirmed by the user.

- Names are untrusted text. They are length-limited and count-limited before the search starts, so a pasted list cannot make the solver run without bound.
- The search has a hard budget per mode and always stops.
- No new API routes and no new dependencies. Layouts are saved through the existing project save, which already validates and size-limits the body.
- Names are only drawn as SVG text nodes, never inserted as markup.

## Out of scope

- Automatic connectors, manual decorative tiles and artwork (Phase 3). Names with no shared letters get the AC11 message until then.
- Crossword cut and score geometry, tile lettering fonts and point values on tiles (Phase 4).
- Dragging the crossword, and the `offset` control (Phase 6).
- SVG export (Phase 7).
- The rule that a character the tile font cannot draw is an error; no tile font is chosen yet.

## Open questions

- Upper limit on names. Proposed: 20 names, 30 characters each. The spec optimises for 2–10.
- Number of candidates shown. Proposed: up to 8.
- The fixed ranking when all weights are zero. Proposed: most intersections, then smallest bounding area, then seed order.
- The exact formulas for compactness and visual balance are not in the spec. They will be documented next to the code and are expected to be tuned by eye.
