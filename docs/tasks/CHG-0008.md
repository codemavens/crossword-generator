# Remaining V1 work: crossword cut geometry, export, project workflow and validation

## Intent

Finish V1 as defined in `../SPEC.md` §26: turn the chosen crossword into real cut, score and engrave geometry, export laser-ready SVG files for all three pieces, complete the design controls and the day-to-day project workflow, and validate the result. This covers Phases 4, 6, 7, 8 and 9 in `../SPEC.md` §21.

## Background

Phases 1–3 and the frame are merged (PRs #1–#6). The app can generate, pick and decorate a crossword and preview it inside the real frame, but the crossword preview is drawn from tile squares, not from cut geometry, and nothing can be exported yet.

The user asked on 2026-11-14 for one brief covering every remaining step so the work can continue while they are away. The work is delivered in four stages, each as its own pull request, in the order below.

Linear tickets: None.

**Status: Draft, awaiting the user's approval.** Approval covers all four stages. Work proceeds from one stage to the next without a further check-in and stops only for a blocker that needs the user's decision.

## Acceptance criteria

### Stage A — Crossword physical geometry (Phase 4)

- AC1: A geometry module in `src/core` turns a layout into Piece 1 in millimetres: the cut outline, the score lines, and the engraving outlines. Every tile is a square of exactly the configured tile size; changing the tile size rescales everything.
- AC2: The cut outline is the union of all occupied squares (letters, punctuation, decorative and blank tiles): one outer closed path, plus one closed path for each enclosed hole. A square shared by two names appears once.
- AC3: Each boundary between two occupied squares is scored exactly once. No score line lies on a cut line, and no cut or score segment is duplicated or overlaps another.
- AC4: Each letter or punctuation tile has its character engraved as a font outline, uppercase, centred in the tile. The tile font is chosen by id from the font registry; the default is Zilla Slab SemiBold. A character the tile font cannot draw is a validation error that names the character.
- AC5: When point values are switched on, each letter tile shows its standard English Scrabble value in the lower-right corner; an accented letter uses its base letter's value; punctuation and decorative tiles show none.
- AC6: Each decorative tile's picture is turned into engraving outlines using the placement rule from CHG-0007 (centred, proportions kept, 15% margin).
- AC7: The app preview draws the crossword from this geometry, with cut, score and engrave shown in distinct colours, so the preview and a later export cannot disagree.

### Stage B — Production export and remaining controls (Phases 6 and 7)

- AC8: The app exports `crossword.svg`, `frame.svg` and `backer.svg`, and an optional `combined.svg` that lays the three pieces side by side with spacing. Files are downloaded by the browser; nothing is written by the server.
- AC9: Every exported file states its physical size with `width` and `height` in millimetres and a matching `viewBox`, so 1 unit is 1 mm.
- AC10: Each file separates operations into named groups with distinct colours: cut, score and engrave. Defaults: cut red `#FF0000`, score blue `#0000FF`, engrave black `#000000`. The three colours are project settings the user can change.
- AC11: Cut and score paths are strokes with no fill; engraving is filled outlines with no stroke. All text is outlines; no file contains a `<text>` element, a font reference, a script, an image or an outside address.
- AC12: In `crossword.svg`, hole cuts come before the outer cut. In `frame.svg`, the outer edge is a true circle and the inner cut is a single path; the name and year are engraving. `backer.svg` is one circle matching the frame's outer edge.
- AC13: Export is not offered when the crossword has structural errors or no arrangement is chosen. When the crossword does not fit the frame, export requires an explicit confirmation and the files are still correct for the pieces as designed.
- AC14: The app has controls for the remaining settings in `../SPEC.md` §18.2: family-name font, year font, tile font (each a choice from the font registry), point values on or off, and the minimum gap between crossword and frame.
- AC15: The app shows sizing and fit feedback: tile size, frame diameter, the crossword's overall width and height in millimetres, whether it fits, and a suggestion to change tile size or diameter when it does not.
- AC16: Automated tests check AC9–AC12 on generated files, and that the exported geometry equals the preview geometry. If Inkscape's command line is available on this machine, a scripted check confirms each exported file's size in millimetres; if it is not, that is reported instead.
- AC17: A short checklist for importing the files into LightBurn (sizes, three operations, cut order) is added under `docs/`, for the user to run. The result of that manual check is not claimed by this task.

### Stage C — Project workflow (Phase 8)

- AC18: The project list can be filtered by project name or customer name.
- AC19: A project can be duplicated; the copy has a new id and a name marked as a copy, and is independent of the original.
- AC20: A project can be exported as a JSON file and imported from one. An imported file goes through the same checks as a normal save, gets a new id, and is refused with a message if it is invalid or too large.
- AC21: A customer proof image of the assembled design (frame, backer, crossword, name and year, without the editing aids) can be downloaded as a PNG.
- AC22: Reopening a saved project reproduces the same design: same arrangement, tiles, pictures and settings.

### Stage D — Validation and handover (Phase 9, automated part)

- AC23: An automated end-to-end test follows `../SPEC.md` §26 steps 2–17 without a browser: create a project, generate, choose, add a decorative tile, set a picture, export the three files, save, reopen, and export again with identical output.
- AC24: Every geometry and export test listed in `../SPEC.md` §20 has an automated test, or is listed in the handover note as needing a person (LightBurn import, Inkscape inspection, laser cutting).
- AC25: A README explains how to install, run and use the tool, and a physical-test checklist lists what to cut and what to measure so the defaults (tile size, diameter, ring width, fonts, colours) can be tuned.
- AC26: `../DEPENDENCIES.md` and `../SPEC.md` are brought up to date with what was built, with dated amendments for any behaviour that differs from the spec text.

### Every stage

- AC27: All tests pass, the typecheck is clean and the build succeeds before a pull request is opened; the stage is checked in a browser where it has a user interface; Codex reviews the branch and its critical and high findings are fixed.

## Constraints / Architecture direction

- Perform implementation and validation in a dedicated task worktree. Preserve the user's original checkout and all existing local changes.
- One pull request per stage into `develop`, in order A to D. If an earlier stage is not merged yet, the next branch is built on top of it and its pull request says so; they are to be merged in order.
- Geometry stays in `src/core`, free of React, DOM and Node, in millimetres. The exporter is a pure function from geometry to SVG text and lives in `src/core`, so the preview, the tests and the download all use the same code.
- The crossword outline is computed exactly from grid edges, not approximated. `clipper2-ts` stays behind the existing polygon module and `opentype.js` behind the typography module. No new dependencies unless a stage cannot be done without one, in which case work stops for approval.
- Geometry is never stored. Only project data is saved, and files are regenerated from it (`../SPEC.md` §14.3).
- Manufacturing sizes are never changed automatically.
- The font registry stays the single place fonts are listed, so the user's later font changes need no code changes elsewhere.
- Keep code comments brief.

## Security considerations

Proposed during drafting; to be confirmed by the user.

- An imported project file is untrusted. It is size-limited, parsed as JSON only, and passed through the same validation as any save, including the artwork checks from CHG-0007. It can never overwrite an existing project because it always gets a new id.
- Exported SVG is built only from application geometry. Names, project names and file names from the user never enter a file as markup; download file names are reduced to safe characters.
- Exported files contain no scripts, links, images or outside references (AC11), so they are safe to open in other tools.
- Export, import and the proof image run in the browser. No new server routes that write files and no calls to outside services. The optional Inkscape check is a developer script, not part of the running app.
- No new permissions, secrets or personal data beyond the customer name already stored locally.

## Out of scope

- Physical laser tests, the LightBurn import itself and final tuning of defaults: these need the user and the machine. Checklists are provided (AC17, AC25).
- Autosave. `../SPEC.md` lists it as optional; explicit Save is kept.
- Dragging the whole crossword, and manual editing beyond end tiles (`../SPEC.md` §10.2, §22).
- Showing sizes in inches. Millimetres only for now.
- New fonts. The two bundled fonts remain until the user supplies the list.
- Outline-only (stroke) artwork conversion, raster images, a shared picture library.
- Blender previews and any of the later features in `../SPEC.md` §22.
- Kerf compensation and structural reinforcement of thin joins.

## Open questions

- Operation colours. Proposed: cut red, score blue, engrave black (AC10), changeable per project. To be confirmed against the user's LightBurn layers.
- Tile font. Proposed: Zilla Slab SemiBold, already bundled; it will change with the user's font list.
- Point values. Proposed: shown by default, standard English Scrabble values.
- Combined sheet spacing. Proposed: 10 mm between pieces, pieces in a row.
- Proof image. Proposed: PNG at 2000 pixels wide.
- Export when the crossword does not fit. Proposed: allowed after an explicit confirmation (AC13), blocked only for structural errors.
- The outline-only upload question from PR #6 is still with the user and is not changed by this task.
