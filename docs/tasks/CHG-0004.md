# Frame prototype: welded family-name frame and backer geometry

## Intent

Generate the real outline of the frame layer and the backer from the project settings, and show it in the app, so the shape can be judged against `../reference/frame-reference.png` and tuned. This is the geometry of Phase 5 in `../SPEC.md` §21, pulled forward by the 2026-11-13 sequencing amendment.

## Background

The frame is the highest-risk part of the product and was misunderstood in earlier planning. `../SPEC.md` §3.3 (as amended under CHG-0003) now defines the V1 shape: inner circle, closed at the bottom by a straight horizontal line, with a close outline around the family name rising above the line, and the year in the solid area below. Phase 1 (PR #1) and the spec amendments (PR #2) are merged into `develop`.

This task is the first to need fonts and the two approved geometry libraries.

Linear tickets: None.

**Status: Approved by the user on 2026-11-13**, with these decisions: Pacifico and Zilla Slab are fine for now and the font list will change later; write a declaration file for `opentype.js`; matching the reference image is the goal; curve the bottom line into the circle if that is not much extra work.

## Acceptance criteria

- AC1: A geometry module in `src/core` takes the family name, optional year, frame settings and parsed fonts, and returns: the frame's outer circle, the frame's single inner cut path, the engraving outlines for the name and year, the backer circle, and the usable opening (polygon and centroid) for later fit checks. All values are in millimetres.
- AC2: The outer edge is represented as an exact circle (centre and radius), not a polygon approximation.
- AC3: The inner cut is one closed path: the inner circle, the bottom line at `bottomLineHeightMm`, and the outline around the family name merged into the solid area below the line. There are no other cut paths, islands or holes.
- AC3a: Where the bottom line meets the inner circle, the corner is rounded with radius `bottomCornerRadiusMm`, so the line curves into the circle. A radius of 0 gives the sharp corner.
- AC4: Every point of the name and year engraving lies inside the wood, at least `nameBufferMm` from the inner cut.
- AC5: The inner cut never dips between letters of the family name at the default smoothness, and a looser smoothness value produces a visibly looser band.
- AC6: The backer circle has the same centre and radius as the frame's outer circle.
- AC7: The app shows the frame layer and backer drawn from this geometry, with the name and year as engraving, and updates when family name, year, outer diameter, ring width, name font size, year font size, buffer, smoothness or bottom-line height is changed.
- AC8: Warnings are shown, without blocking, when the family name is wider than the opening at the line, or the year does not fit in the solid area below the line.
- AC9: A project saved before this change opens with defaults for the new frame settings (`bottomLineHeightMm`, `crosswordClearanceMm` = 5).
- AC10: Automated tests cover AC2–AC6 and AC9 for at least three names: a short one, a long one, and one with an accented letter. The same inputs always produce the same geometry.
- AC11: `opentype.js` and `clipper2-ts` are added at exact versions and recorded in `../DEPENDENCIES.md`. Bundled fonts are recorded there with their licence, and each font's licence file is in the repository.
- AC12: A side-by-side comparison of the app's output for "The Sanders" / "2026" against the reference image is included in the PR for the user to judge.

## Constraints / Architecture direction

- Perform implementation and validation in a dedicated task worktree. Preserve the user's original checkout and all existing local changes.
- Follow `../SPEC.md` §3 and §4 as amended. The reference image governs where it and the text disagree.
- `clipper2-ts` owns every union, difference and offset. `opentype.js` owns glyph outlines. Paper.js is not installed.
- Third-party libraries sit behind application-owned interfaces in `src/core`, which stays free of React, the DOM and Node. Font bytes are loaded by the app or the tests and passed in.
- The bottom edge of the opening is a replaceable step. The rounded corner (AC3a) is the low-cost form of the curve the user prefers; a fully curved bottom edge stays a later improvement.
- Fonts are referenced by id through a small registry, so the list can change later without touching the geometry.
- The preview draws from the same geometry values an exporter will later use.
- Keep code comments brief.

## Security considerations

Proposed during drafting; to be confirmed by the user.

- Family name and year are untrusted text. They are length-limited and only ever turned into geometry, never inserted into the page as markup.
- Fonts are bundled files from the repository. No font upload and no network font loading is added.
- No new API routes. The two new libraries run in the browser and in tests only.

## Out of scope

- SVG file export and LightBurn checks (Phase 7).
- Crossword tile geometry, the solver and connectors.
- A fully curved bottom edge (the rounded corners in AC3a are in scope).
- Final defaults for diameter, ring width and font sizes; these are tuned later with physical tests.
- A font picker. One font each for name and year is wired in.
- The `decorativeTiles` rename and `anchor` fields in the code models; those wait for the solver phase.

## Open questions

- The user understood `opentype.js` to be deprecated. On 2026-11-13 the npm registry showed no deprecation notice, version 2.0.0 was published in May 2026, and the GitHub repository was not archived. It stays behind an application-owned interface so it can be replaced.
- Default smoothness, line height and corner radius are chosen by eye against the reference image and are expected to change.
- The security considerations above were proposed during drafting and approved as part of the brief without separate discussion.
