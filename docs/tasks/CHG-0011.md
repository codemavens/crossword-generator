# Generate and show the crossword as names are entered

## Intent

Today the preview stays empty with "Generate to see arrangements." until the user goes to the Arrangement step and presses Generate, then picks an arrangement. Instead, the crossword should appear in the preview as soon as names are entered in the Details step, and update whenever a name is added, edited or removed. The first generated arrangement is used automatically. The Arrangement step remains the place to pick a different one.

## Background

Mike finds the current flow unhelpful: entering names gives no visual result, and the empty-preview prompt sends the user to another step before anything is shown.

Linear tickets: None.

## Acceptance criteria

- AC1: With a frame available and at least one valid name, entering names in the Details step generates arrangements without pressing Generate, and the first arrangement in the generated list is selected and drawn in the preview.
- AC2: Adding, editing or removing a name generates again and replaces the crossword shown with the first arrangement of the new result. Generation waits for a short pause in typing, and a newer change supersedes a run still in progress.
- AC3: A name change always regenerates, even when the current arrangement has custom work (moved position, tile pictures, removed decorative tiles). That work is not carried over.
- AC4: Automatic generation uses the project's current solver settings (mode, seed, weights). It gives the same result as pressing Generate with the same names and settings.
- AC5: The Arrangement step lists the automatically generated arrangements with the first one marked as chosen, so the user can pick another without generating again. The Generate button, mode, seed and weights still work as before.
- AC6: Opening a saved project whose arrangement still matches its names does not regenerate or change that arrangement. A saved project whose arrangement no longer matches its names, or that has valid names and no arrangement, generates automatically.
- AC7: Changes to frame, tile size, fonts or solver settings do not trigger automatic generation; only name changes do (plus AC6 on open).
- AC8: While a run is in progress the preview says so. If names are invalid, there is no frame, or generation fails, no crossword is drawn and the preview shows the reason in place of "Generate to see arrangements."
- AC9: The outcome of an automatic run is announced through the existing live region, as for a manual run.
- AC10: Tests cover the decision of when to auto-generate and which arrangement is chosen. `README.md`, `docs/SPEC.md` (amendment) and `docs/handover.md` describe the new flow.

## Constraints / Architecture direction

- Perform implementation and validation in a dedicated task worktree. Preserve the user's original checkout and all existing local changes.
- Reuse the existing solver worker and client; no change to the solver itself or to saved project data.
- Keep the step rail rules as they are: the Arrangement step is complete once an arrangement is chosen, which now happens automatically.
- Keep the decision logic (when to run, what to select) in a pure, testable function, as `steps.ts` does for step state.

## Security considerations

None. The change only alters when the existing in-browser solver runs; there is no new data, endpoint or permission.

## Out of scope

- Changing the solver, its scoring or its default settings.
- Removing or redesigning the Arrangement step.
- Keeping custom tile work across a name change.
- Regenerating when the frame or tile size changes.
